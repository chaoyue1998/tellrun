# Tellrun 产品需求文档

本产品供本人通过 Telegram 私聊，操作服务器项目中的 Codex：提交任务、继续对话、查看进度、处理审批和停止执行。首版以稳定完成这条交互链路为目标。

已确认约束：Node.js + TypeScript；个人使用；先接 Telegram 和 Codex；通过 npm 全局安装，在命令行交互配置后于服务器后台运行；后续逐步接入其他 IM 与 Claude 等 Agent。当前已接入会话管理、串行执行与恢复，下文为完整首版目标；实际实现范围见项目 README。版本为 v0.1，日期为 2026 年 10 月 28 日。

[架构与技术选型](architecture.md)

## 产品目标与首版边界

用户离开电脑后，仍可在手机上继续服务器里的开发任务，并清楚知道任务的工作目录、是否仍在运行、是否等待自己处理。

支持单台 Linux 服务器或 Mac、一个 Telegram Bot、一个授权用户，入口限定为私聊。需要持续在线时建议使用 Linux 服务器；macOS 用户服务要求桌面保持登录，休眠期间无法持续处理消息。

| 范围 | 首版决定 |
| --- | --- |
| 用户 | 本人；以 Telegram 数字用户 ID 授权 |
| IM | Telegram 私聊，长轮询 |
| Agent | Codex；复用服务器上的登录与配置 |
| 工作目录 | 由任务或会话指定，不设置项目清单或目录白名单 |
| 会话 | 可新建、选择和继续多个 Agent 会话 |
| 执行 | 全局同时执行一个编码任务；同一聊天的新消息直接补充到当前任务 |
| 交互 | 文本、图片与文件输入、进度消息、审批按钮、补充问题、停止任务 |
| 安装与配置 | npm install -g tellrun，安装后通过 CLI 配置向导完成初始化 |
| 部署 | 一个 Node.js 常驻后台服务；Linux 使用 systemd 用户服务，macOS 使用 launchd 用户服务 |

图片与文件接收已支持：照片使用原生视觉输入，普通文件下载到本地供 Codex 读取，支持附带说明和执行中追加。定时任务支持五段 Cron 表达式和服务内调度。语音、文件回传、群聊与论坛话题、Web 管理界面、多人权限及计费放在后续版本。其他 IM 和 Claude 等 Agent 分别按实际需求增加。

## 安装与后台管理

使用者在服务器安装 Node.js、Codex 并完成 Codex 认证后，通过 `npm install -g tellrun` 安装程序。运行 `tellrun setup`，以明文输入 Telegram Bot Token 并填写本人 ID，检查 Codex 可用性，保存配置后可启动或重启后台服务。配置文件不保存终端环境；可选的 `telegram.proxyUrl` 由用户自行配置，未设置时继承运行环境的代理。CLI 与后台管理已接入，npm 发布与 Linux 实际部署验收仍待完成；安装用户无需克隆源码或手动复制 `.env`。

提供 start、stop、restart、status 和 logs 命令，另提供前台 run 用于诊断。停止须等待实际退出，重复启动不创建多份服务；启动失败时给出原因和日志入口。配置向导在 Linux 检查退出 SSH 后持续运行的条件并提供开机自启，在 macOS 提供登录自启。macOS 使用当前用户的 LaunchAgent，无需管理员权限，注销后停止；两种后台均在 Telegram 初始化成功后才报告就绪。

配置和运行状态统一保存在当前用户的 `~/.tellrun/`，分别为 `config.json` 和 `state.json`；临时锁和服务定义也保存到该目录，与 npm 安装目录及执行命令时的目录无关。macOS 登录自启入口链接到用户的 Library/LaunchAgents 目录。Linux 服务诊断日志由 journal 保存，macOS 写入 tellrun.log，不重复保存 Codex 任务历史。升级包保留原有配置和必要运行状态；卸载服务不自动删除用户数据或关闭 Linux 用户 linger。配置过程中取消或校验失败不覆盖原配置。

## 核心使用流程

1. 首次私聊机器人，进入或新建 Agent 会话。

2. 未指定工作目录时默认沿用服务启动目录，也可通过 `/cwd 绝对路径` 切换；后续对话沿用该会话的目录。

3. 用户发送文字、图片或文件及任务说明，执行时客户端显示“正在输入…”，不发送固定接收回执；执行中的新消息补充给 Codex，附件先下载再提交，无法接收时给出明确提示。

4. 回复生成时即可看到流式文字，客户端逐步显示新增内容；当前阶段、工具活动摘要和耗时属于后续进度能力。

5. 需要授权时，机器人发送审批消息；需要澄清时，发送问题和可选答案。

6. 用户批准、拒绝、补充输入，或停止任务。

7. 完成后收到结论、修改摘要、实际执行的检查及未完成事项；后续消息可继续该会话。

示例：发送“在 /srv/my-site 中分析登录失败的原因” → 查看分析 → 发送“按这个方案修复” → 处理需要授权的操作 → 查看结果。无需事先登记目录或选择项目。

## 命令与消息体验

| 入口 | 行为 |
| --- | --- |
| /start 或 /help | 展示使用说明和常用命令 |
| /cwd [绝对路径] | 无参数时查看当前目录；指定目录时切换工作目录并开始新会话，任务运行中禁止切换 |
| /new [名称] | 创建并切换到新会话，省略名称时使用默认名称；任务运行中禁止创建 |
| /model | 显示当前模型与推理强度，先选模型再选支持的推理档位，两步完成后用于后续任务 |
| /permissions | 选择后续任务的权限模式，执行中的任务保持原权限 |
| /list | 显示当前项目最近最多 10 个会话按钮和点击切换提示，当前会话以 ✓ 标记；任务运行中可查看，禁止切换 |
| /cron | 列出定时任务，并通过 add、del、enable、disable 管理计划 |
| /status | 显示 Tellrun 版本与更新提示、工作目录、模型名称与推理档位（如 GPT-6-Sol · xhigh）、权限、任务和服务状态；未选择时解析 Codex 配置，任务模型或档位不同时分别显示 |
| /update | 将当前 Tellrun 实例的版本、安装位置和升级要求交给 Codex，按当前会话与权限创建普通任务；忙碌或暂停时提示处理后重试 |
| /restart | 重启 Tellrun 并重新读取配置，保留会话、暂停状态与后台任务，连接恢复后回复；Linux 和 macOS 的前台及后台运行均支持 |
| /last | 查看当前聊天最近已结束任务的状态与结果 |
| /stop | 请求停止当前聊天的活动任务，暂停新任务和定时调度，并清空等待触发 |
| /resume | 当前任务结束后恢复接收新任务和未来的定时调度，不重跑已中断的任务 |
| 普通文本 | 空闲时开始新任务；执行中立即补充到当前任务 |
| 审批或问题按钮 | 立即处理，不进入编码任务队列 |

独立任务队列、`/queue` 及“继续排队／清空队列”按钮留到后续实现。当前通过 `/stop` 暂停、`/last` 查看结果、`/resume` 恢复接收；已接收任务保留提交时的会话与工作目录。存在问题时，只有点击选项或明确回复该问题消息才作为答案，避免把另一条需求误当作审批或答案。

流式草稿最多每秒更新一次，控制命令回复和完成状态优先发送。草稿、最终回复和 /last 支持 Markdown 标题、列表、表格和代码块；预览展示当前完整输出，超过单条富消息容量时等待最终分段发送。最终长回复按 Telegram 限制拆分并标记顺序，跨段代码块保持围栏完整，保留完整结果供再次查看；Markdown 被拒绝时保留原文发送。模型表达的结论和程序确认的任务状态分开处理：只能依据执行事件判断是否完成，不能仅因回复里出现“完成”就标记成功。

Telegram 支持长轮询，服务器主动接收更新；这种部署方式无需公开 Webhook 接收地址。[grammY 部署说明](https://grammy.dev/guide/deployment-types)

## 定时任务

定时任务通过 Telegram 私聊管理，命令格式如下：

| 命令 | 行为 |
| --- | --- |
| `/cron` | 列出当前聊天的全部计划，包括 ID、启用状态、表达式、时区、目录、任务描述和下次执行时间 |
| `/cron add <分> <时> <日> <月> <周> <任务描述>` | 创建并启用计划，例如 `/cron add 0 9 * * 1-5 检查项目并汇报问题` |
| `/cron del <id>` | 删除计划及其待执行触发 |
| `/cron enable <id>` | 启用计划，从下一个匹配时间开始；重复启用不清空已有等待 |
| `/cron disable <id>` | 禁用计划并清空待执行触发 |

使用开源 Croner 校验与解析五段表达式，支持 `*`、列表、范围和步长，周日可用 `0` 或 `7`；“日”和“周”同时限定时默认采用 OR 规则。创建时保存服务器时区，列表明确显示该时区，后续服务器时区变化不修改已有计划。[Croner 表达式说明](https://croner.56k.guru/usage/pattern/)

计划固定创建时的目录、模型、推理强度和权限选择；没有手动选择的模型项继续沿用该目录的 Codex 默认配置。每次执行创建独立会话，保持手动聊天的会话绑定。执行复用现有审批、补充输入、停止和结果投递流程，开始与结束消息标注 Cron ID；`/status` 在实际任务目录不同于当前聊天目录时单独展示任务目录。

Tellrun 在线且聊天未暂停时触发，全局只执行一个任务。忙碌期间每个计划最多保留一次待执行，重复到期合并，空闲时按首次等待时间依次执行。`/stop` 停止当前任务、清空当前聊天的等待触发并暂停调度；`/resume` 后从下个匹配时点继续。删除或禁用计划不会中断已经进入执行流程的任务，需要停止时使用 `/stop`。

计划与待执行触发随状态保存，重启后恢复。停机期间错过的触发不补跑；停机前已经保存的待执行项仍保留。已确认的活动轮次恢复跟踪，执行结果不确定时沿用现有暂停与不重放规则。调度只属于当前机器人和授权用户，控制命令重复投递不会重复创建计划，删除后的 ID 不复用。

## 审批与异常行为

默认建议使用 Codex 的工作区写入权限与按需审批策略。允许范围内的操作可直接执行；只有 Codex 明确发起的审批请求才显示审批交互，因此不是每一条命令都弹出按钮。操作范围受运行时实际配置和托管策略约束。[Codex 审批说明](https://learn.chatgpt.com/docs/app-server#approvals)

`/permissions` 固定提供 Codex CLI 0.165.0 的 Ask for approval、Approve for me、Full Access 和 Read Only 四种模式，默认 Ask for approval。模式在提交任务时形成快照，执行中的新选择只影响后续任务；`/status` 区分所选模式与当前任务模式。选择跨重启保存，`/new` 沿用选择，切换目录恢复默认。可用性由 Codex 在启动任务时校验，拒绝或返回设置不符时不提交任务；本次不提供自定义 permission profile 发现。

| 情况 | 产品行为 |
| --- | --- |
| 需要执行授权 | 显示工作目录、操作内容和原因；按 Codex 请求提供本次允许、会话内允许、记住规则、拒绝或取消，审批卡片不提供 Stop |
| 需要补充信息 | 展示问题；选项或明确回复可作为答案 |
| 审批超时 | 使按钮失效并说明原因；拒绝该请求或停止等待，按请求类型处理 |
| 重复或旧按钮 | 提示已处理或已失效，不再次执行 |
| 用户拒绝操作 | 将拒绝交给 Codex；若它继续提出可行方案，保持当前任务 |
| 用户停止 | 请求中断；终态确认前保持“正在停止”；无法确认时显示异常中断 |
| Telegram 暂时断线 | 服务保留任务状态；恢复后补发必要的结果或待处理通知 |
| Codex 进程异常退出 | 将活动任务标记异常中断，保留上下文和错误信息 |
| 服务停止或重启 | Codex 独立后台继续执行；重连已确认轮次并补回结果，不重复提交任务 |
| 收到重复消息事件 | 复用已有任务记录，不重新执行编码任务 |

停止 Tellrun 只停止消息连接；`/stop` 或问题卡片的 Stop 按钮取消 Codex 当前轮次并暂停接收。审批 Cancel 交给 Codex 处理，不暂停聊天。重启后根据已保存的会话与轮次 ID 恢复跟踪，离线期间完成的结果也会补回。尚未确认派发、旧状态缺少轮次 ID，或 Codex 后台自身异常退出时，先展示不确定状态，不自动重跑。

## 数据与运行要求

图片与文件接收沿用本人授权、消息去重和任务会话绑定。单附件最多 20 MB；下载独立于控制指令，超限、下载失败或保存失败明确提示。JPEG、PNG、WebP 和 GIF 按文件头识别为图片，其他文件以本地路径交给 Codex；文档解析依赖服务器上的工具。附件保存在 `~/.tellrun/attachments/`，同名上传互不覆盖，下载失败或取消时清理未完成文件。成功接收的附件供后续对话使用，由用户在不再需要时清理。下载阶段的任务和补充输入可在重启后重新准备，已进入提交阶段但结果不确定的输入不重放。

任务使用用户指定或当前会话沿用的工作目录，Tellrun 不限制项目目录，也不要求项目配置文件。本地 JSON 仅保存会话绑定、活动任务、每个聊天的最近结果、定时计划与待执行触发，以及尚未完成的交互与投递状态。去重标识在 Telegram 确认后回收；关闭的交互待关联消息清理完成后回收；回复发送成功或永久拒绝后移出队列。历史任务不会持续累积，发送故障期间仍保留未完成的投递。Codex 原生历史由 Codex 管理，Tellrun 不另存任务日志、完整上下文、流式文本或工具原始输出。恢复服务需要保留配置、状态文件和相应 Codex 会话数据。

聊天文本通过 Telegram 传递，模型请求按 Codex 配置发往相应服务。Bot Token 等凭据从服务环境或受限配置读取；Tellrun 日志仅记录服务启停、连接与存储故障，不记录任务过程、凭据及聊天正文。

以下是首版验收目标，执行时延不包括模型生成耗时及外部网络故障：

- 正常网络下，收到消息后目标 2 秒内给出接收或排队反馈。

- 编码任务运行时，状态查询、审批和停止仍可处理。

- 在两个工作目录中使用不同会话，消息、审批和结果归属正确。

- 重复投递同一消息，不增加第二个编码任务。

- Tellrun 停止或重启不取消 Codex 任务；重连后恢复原轮次与结果，不自动重跑结果不确定的操作。

- 运行 24 小时并完成一次网络恢复、一次进程故障演练后，能够继续处理新任务。

- 从发布包全局安装后，在任意目录均可配置并启停服务；完成后台设置后，退出 SSH 仍能接收消息，升级后配置和必要运行状态保留。

## 实施阶段与扩展方向

当前支持直接发送普通消息给 Codex 并沿用会话，默认使用服务启动目录，`/cwd 绝对路径` 可选；支持 `/new [名称]`、`/list`、`/status`、`/stop`、`/resume`、`/last`，通过 `/list` 的按钮切换会话。任务运行中可列出会话，禁止新建和切换；新建和切换保留模型与权限选择。执行中的新文本通过 turn/steer 补充到当前任务。已接入命令、文件和权限审批按钮，以及结构化问题的选项和明确回复；多题收齐后提交，普通消息继续补充任务。旧交互在停止、结束、到期或重启后失效，批准不自动重放；非阻塞问题到期不代选答案，任务继续。敏感输入、MCP 表单／URL 和动态工具请求仍明确中断。

审批与提问已按本机 Codex CLI 0.165.0 生成协议核对，并通过存储、stdio／WebSocket 和 Telegram API 模拟验证。真实 Telegram 操作和目标 Linux 部署仍需验收，通用任务队列与工具进度摘要仍待实现。

| 阶段 | 交付 | 进入下一阶段的条件 |
| --- | --- | --- |
| M0 协议验证 | 在目标 Linux 环境验证 Codex 的会话、事件、审批、提问和中断 | 固定可用的 Codex 版本及协议类型，关键交互通过 |
| M1 基础链路 | 本人私聊、明确工作目录、单会话执行；同时具备去重、任务与发送持久化、单实例约束、最小停止和中断恢复 | 可执行并续聊；重复事件不重复执行；未知审批明确拒绝或中断；断线和重启不重放不确定任务 |
| M2 可用首版 | 多会话、队列管理、完整审批与补充输入、恢复操作界面 | P0 功能与异常验收通过 |
| M3 安装与日常运行 | npm 全局发布、CLI 配置向导、后台服务管理、升级、备份、日志与持续运行检查 | 安装后可交互配置并后台运行；退出 SSH、重启和升级行为符合约定 |
| 后续 IM 扩展 | 增加一个实际需要的 IM | 原有 Codex 与任务流程保持一致 |
| 后续 Agent 扩展 | 接入 Claude 等新的运行时 | 先核对其会话、审批和停止能力，再实现对应适配 |

产品名称为 Tellrun（Tell + Run），npm 包名与 CLI 命令均为 `tellrun`。服务器系统、部署目录及首个扩展对象在相应实施阶段确定。当前不提供项目列表或项目选择流程。
