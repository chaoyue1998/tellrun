# Tellrun 产品需求文档

本产品供本人通过 Telegram 私聊，操作服务器项目中的 Codex：提交任务、继续对话、查看进度、处理审批和停止执行。首版以稳定完成这条交互链路为目标。

已确认约束：Node.js + TypeScript；个人使用；先接 Telegram 和 Codex；通过 npm 全局安装，在命令行交互配置后于服务器后台运行；后续逐步接入其他 IM 与 Claude 等 Agent。当前已接入单会话执行与恢复，下文为完整首版目标；实际实现范围见项目 README。版本为 v0.1，日期为 2026 年 10 月 28 日。

[架构与技术选型](architecture.md)

## 产品目标与首版边界

用户离开电脑后，仍可在手机上继续服务器里的开发任务，并清楚知道任务的工作目录、是否仍在运行、是否等待自己处理。

支持单台 Linux 服务器或 Mac、一个 Telegram Bot、一个授权用户，入口限定为私聊。需要持续在线时建议使用 Linux 服务器；macOS 用户服务要求桌面保持登录，休眠期间无法持续处理消息。

| 范围 | 首版决定 |
| --- | --- |
| 用户 | 本人；以 Telegram 数字用户 ID 授权 |
| IM | Telegram 私聊，长轮询 |
| Agent | Codex；复用服务器上的登录与配置 |
| 工作目录 | 由任务或会话指定，不设置项目清单或目录白名单 |
| 会话 | 可新建、选择和继续多个 Agent 会话 |
| 执行 | 全局同时执行一个编码任务；同一聊天的新消息直接补充到当前任务 |
| 交互 | 文本、进度消息、审批按钮、补充问题、停止任务 |
| 安装与配置 | npm install -g tellrun，安装后通过 CLI 配置向导完成初始化 |
| 部署 | 一个 Node.js 常驻后台服务；Linux 使用 systemd 用户服务，macOS 使用 launchd 用户服务 |

图片、语音、通用文件传输、群聊与论坛话题、Web 管理界面、定时任务、多人权限及计费放在后续版本。其他 IM 和 Claude 等 Agent 分别按实际需求增加。

## 安装与后台管理

使用者在服务器安装 Node.js、Codex 并完成 Codex 认证后，通过 `npm install -g tellrun` 安装程序。运行 `tellrun setup`，以明文输入 Telegram Bot Token 并填写本人 ID，检查 Codex 可用性，保存配置后可启动或重启后台服务。配置文件不保存终端环境；可选的 `telegram.proxyUrl` 由用户自行配置，未设置时继承运行环境的代理。CLI 与后台管理已接入，npm 发布与 Linux 实际部署验收仍待完成；安装用户无需克隆源码或手动复制 `.env`。

提供 start、stop、restart、status 和 logs 命令，另提供前台 run 用于诊断。停止须等待实际退出，重复启动不创建多份服务；启动失败时给出原因和日志入口。配置向导在 Linux 检查退出 SSH 后持续运行的条件并提供开机自启，在 macOS 提供登录自启。macOS 使用当前用户的 LaunchAgent，无需管理员权限，注销后停止；两种后台均在 Telegram 初始化成功后才报告就绪。

配置和运行状态统一保存在当前用户的 `~/.tellrun/`，分别为 `config.json` 和 `state.json`；临时锁和服务定义也保存到该目录，与 npm 安装目录及执行命令时的目录无关。macOS 登录自启入口链接到用户的 Library/LaunchAgents 目录。Linux 服务诊断日志由 journal 保存，macOS 写入 tellrun.log，不重复保存 Codex 任务历史。升级包保留原有配置和必要运行状态；卸载服务不自动删除用户数据或关闭 Linux 用户 linger。配置过程中取消或校验失败不覆盖原配置。

## 核心使用流程

1. 首次私聊机器人，进入或新建 Agent 会话。

2. 未指定工作目录时默认沿用服务启动目录，也可通过 `/cwd 绝对路径` 切换；后续对话沿用该会话的目录。

3. 用户发送任务，执行时客户端显示“正在输入…”，不发送固定接收回执；执行中的新消息立即补充给 Codex，无法接收时给出明确提示。

4. 回复生成时即可看到流式文字，客户端逐步显示新增内容；当前阶段、工具活动摘要和耗时属于后续进度能力。

5. 需要授权时，机器人发送审批消息；需要澄清时，发送问题和可选答案。

6. 用户批准、拒绝、补充输入，或停止任务。

7. 完成后收到结论、修改摘要、实际执行的检查及未完成事项；后续消息可继续该会话。

示例：发送“在 /srv/my-site 中分析登录失败的原因” → 查看分析 → 发送“按这个方案修复” → 处理需要授权的操作 → 查看结果。无需事先登记目录或选择项目。

## 首版功能要求

| 编号 | 功能 | 用户可见行为 | 验收条件 |
| --- | --- | --- | --- |
| P0 01 | 本人授权 | 只有配置的本人可操作机器人 | 其他用户的消息和按钮回调均不能创建任务、读取结果或批准操作 |
| P0 02 | 工作目录 | 直接指定任务工作目录 | 无需预先登记目录；已排队任务保留提交时的目录 |
| P0 03 | 会话管理 | 新建、列出、选择和续聊 | 两个会话不串上下文；正常重启后可继续已保存的会话 |
| P0 04 | 执行中补充 | 普通新消息直接补充到当前 Codex 任务 | 无需等待任务完成；重复事件不重复提交；补充失败明确提示 |
| P0 05 | 流式输出与结果 | 生成过程中显示文本，结束后保存完整回复 | 首段文字不等待任务结束；成功、失败、主动停止和异常中断分别展示 |
| P0 06 | 执行审批 | 显示操作及允许或拒绝按钮 | 按钮只作用于对应操作；过期和重复点击不产生额外执行 |
| P0 07 | 补充问题 | 显示选项，支持明确回复问题 | 答案进入对应问题；其他普通消息作为任务补充输入 |
| P0 08 | 停止任务 | 显示“正在停止”，随后给出停止结果 | 停止指令不被编码任务阻塞；未确认结束前不显示“已停止” |
| P0 09 | 故障恢复 | 展示异常中断及后续处理入口 | 不自动重放执行结果不确定的任务 |
| P0 10 | 服务状态 | 查看工作目录、模型、权限、任务和连接状态 | 编码任务执行或等待审批时，状态查询仍能响应 |

## 命令与消息体验

| 入口 | 行为 |
| --- | --- |
| /start 或 /help | 展示使用说明、当前会话和常用操作 |
| /new | 新建 Agent 会话 |
| /model | 显示当前模型与推理强度，先选模型再选支持的推理档位，两步完成后用于后续任务 |
| /permissions | 选择后续任务的权限模式，执行中的任务保持原权限 |
| /sessions | 分页列出会话，点击切换 |
| /status | 显示工作目录、模型、权限、任务和服务状态；任务模型与当前选择不同时分别显示 |
| /queue | 查看排队任务，通过按钮取消指定任务 |
| /stop | 停止当前聊天的活动任务，并暂停该聊天后续队列 |
| 普通文本 | 空闲时开始新任务；执行中立即补充到当前任务 |
| 审批或问题按钮 | 立即处理，不进入编码任务队列 |

停止后提供“继续排队”和“清空队列”按钮。已接收任务保留提交时的会话与工作目录。存在问题时，只有点击选项或明确回复该问题消息才作为答案，避免把另一条需求误当作审批或答案。

流式草稿最多每秒更新一次，控制命令回复和完成状态优先发送。预览显示当前回复末尾 2000 个 Unicode 字符；最终长回复按 Telegram 限制拆分并标记顺序，保留完整结果供再次查看。模型表达的结论和程序确认的任务状态分开处理：只能依据执行事件判断是否完成，不能仅因回复里出现“完成”就标记成功。

Telegram 支持长轮询，服务器主动接收更新；这种部署方式无需公开 Webhook 接收地址。[grammY 部署说明](https://grammy.dev/guide/deployment-types)

## 审批与异常行为

默认建议使用 Codex 的工作区写入权限与按需审批策略。允许范围内的操作可直接执行；只有 Codex 明确发起的审批请求才显示审批交互，因此不是每一条命令都弹出按钮。操作范围受运行时实际配置和托管策略约束。[Codex 审批说明](https://learn.chatgpt.com/docs/app-server#approvals)

`/permissions` 固定提供 Codex CLI 0.165.0 的 Ask for approval、Approve for me、Full Access 和 Read Only 四种模式，默认 Ask for approval。模式在提交任务时形成快照，执行中的新选择只影响后续任务；`/status` 区分所选模式与当前任务模式。选择跨重启保存，`/new` 沿用选择，切换目录恢复默认。可用性由 Codex 在启动任务时校验，拒绝或返回设置不符时不提交任务；本次不提供自定义 permission profile 发现。

| 情况 | 产品行为 |
| --- | --- |
| 需要执行授权 | 显示工作目录、操作内容和原因；提供本次允许、拒绝、停止任务 |
| 需要补充信息 | 展示问题；选项或明确回复可作为答案 |
| 审批超时 | 使按钮失效并说明原因；拒绝该请求或停止等待，按请求类型处理 |
| 重复或旧按钮 | 提示已处理或已失效，不再次执行 |
| 用户拒绝操作 | 将拒绝交给 Codex；若它继续提出可行方案，保持当前任务 |
| 用户停止 | 请求中断；终态确认前保持“正在停止”；无法确认时显示异常中断 |
| Telegram 暂时断线 | 服务保留任务状态；恢复后补发必要的结果或待处理通知 |
| Codex 进程异常退出 | 将活动任务标记异常中断，保留上下文和错误信息 |
| 服务停止或重启 | Codex 独立后台继续执行；重连已确认轮次并补回结果，不重复提交任务 |
| 收到重复消息事件 | 复用已有任务记录，不重新执行编码任务 |

停止 Tellrun 只停止消息连接；显式停止任务（`/stop` 或停止按钮）才取消 Codex 当前轮次。重启后根据已保存的会话与轮次 ID 恢复跟踪，离线期间完成的结果也会补回。尚未确认派发、旧状态缺少轮次 ID，或 Codex 后台自身异常退出时，先展示不确定状态，不自动重跑。

## 数据与运行要求

任务使用用户指定或当前会话沿用的工作目录，Tellrun 不限制项目目录，也不要求项目配置文件。本地 JSON 仅保存会话绑定、活动任务、每个聊天的最近结果，以及尚未完成的交互与投递状态。去重标识在 Telegram 确认后回收；关闭的交互待关联消息清理完成后回收；回复发送成功或永久拒绝后移出队列。历史任务不会持续累积，发送故障期间仍保留未完成的投递。Codex 原生历史由 Codex 管理，Tellrun 不另存任务日志、完整上下文、流式文本或工具原始输出。恢复服务需要保留配置、状态文件和相应 Codex 会话数据。

聊天文本通过 Telegram 传递，模型请求按 Codex 配置发往相应服务。Bot Token 等凭据从服务环境或受限配置读取；Tellrun 日志仅记录服务启停、连接与存储故障，不记录任务过程、凭据及聊天正文。

以下是首版验收目标，执行时延不包括模型生成耗时及外部网络故障：

- 正常网络下，收到消息后目标 2 秒内给出接收或排队反馈。

- 编码任务运行时，状态查询、审批和停止仍可处理。

- 在两个工作目录中使用不同会话，消息、审批和结果归属正确。

- 重复投递同一消息，不增加第二个编码任务。

- Tellrun 停止或重启不取消 Codex 任务；重连后恢复原轮次与结果，不自动重跑结果不确定的操作。

- 运行 24 小时并完成一次网络恢复、一次进程故障演练后，能够继续处理新任务。

- 从发布包全局安装后，在任意目录均可配置并启停服务；完成后台设置后，退出 SSH 仍能接收消息，升级后配置和必要运行状态保留。

## 实施阶段与扩展方向

当前支持直接发送普通消息给 Codex 并沿用会话，默认使用服务启动目录，`/cwd 绝对路径` 可选；支持 `/new`、`/status`、`/stop`、`/resume`、`/last`。执行中的新文本通过 turn/steer 补充到当前任务。已接入命令、文件和权限审批按钮，以及结构化问题的选项和明确回复；多题收齐后提交，普通消息继续补充任务。旧交互在停止、结束、到期或重启后失效，批准不自动重放；非阻塞问题到期不代选答案，任务继续。敏感输入、MCP 表单／URL 和动态工具请求仍明确中断。

审批与提问已按本机 Codex CLI 0.165.0 生成协议核对，并通过存储、stdio／WebSocket 和 Telegram API 模拟验证。真实 Telegram 操作和目标 Linux 部署仍需验收，多会话、任务队列与工具进度摘要仍待实现。

| 阶段 | 交付 | 进入下一阶段的条件 |
| --- | --- | --- |
| M0 协议验证 | 在目标 Linux 环境验证 Codex 的会话、事件、审批、提问和中断 | 固定可用的 Codex 版本及协议类型，关键交互通过 |
| M1 基础链路 | 本人私聊、明确工作目录、单会话执行；同时具备去重、任务与发送持久化、单实例约束、最小停止和中断恢复 | 可执行并续聊；重复事件不重复执行；未知审批明确拒绝或中断；断线和重启不重放不确定任务 |
| M2 可用首版 | 多会话、队列管理、完整审批与补充输入、恢复操作界面 | P0 功能与异常验收通过 |
| M3 安装与日常运行 | npm 全局发布、CLI 配置向导、后台服务管理、升级、备份、日志与持续运行检查 | 安装后可交互配置并后台运行；退出 SSH、重启和升级行为符合约定 |
| 后续 IM 扩展 | 增加一个实际需要的 IM | 原有 Codex 与任务流程保持一致 |
| 后续 Agent 扩展 | 接入 Claude 等新的运行时 | 先核对其会话、审批和停止能力，再实现对应适配 |

产品名称为 Tellrun（Tell + Run），npm 包名与 CLI 命令均为 `tellrun`。服务器系统、部署目录及首个扩展对象在相应实施阶段确定。当前不提供项目列表或项目选择流程。
